LM-Studio为A机,AnythingLLM为B机,设置
1 .	这正是大模型网络化部署的经典玩法。
2 .
3 .	AnythingLLM 本身就是一个纯客户端，它支持通过局域网（IP 地址）去调用另一台电脑上的大模型算力。在这种架构下：
4 .
5 .	A 机（算力机）：负责最吃硬件的模型加载和推理计算。
6 .	B 机（客户机）：负责运行 AnythingLLM 的界面、管理知识库（RAG），通过网络向 A 机发送请求。
7 .
8 .	为了让 B 机能顺利连上 A 机的 LM Studio，你需要对两台电脑进行简单的配置。具体操作步骤如下：
9 .------------------
10.
11.第一步：确保两台电脑在同一个局域网
12.
13.	1. 确认 A 机和 B 机连接在 同一个路由器 的 Wi-Fi 或网线上。
14.	2. 获取 A 机的局域网 IP 地址 ：
15.	 在 A 机上按下 `Win + R`，输入 `cmd` 回车。
16.	 输入 `ipconfig` 并回车。
17.	 找到你当前联网网卡（以太网或无线局域网）下的  IPv4 地址 （通常是 `192.168.x.x` 或 `10.x.x.x`，假设这里是 `192.168.1.50`）。
18.
19.第二步：修改 A 机 LM Studio 的服务器设置（关键）
20.
21.	默认情况下，LM Studio 的服务器只允许 A 机自己访问（绑定为 `localhost` 或 `127.0.0.1`）。要让局域网内的 B 机也能访问，需要修改监听地址：
22.
23.	1. 在 A 机上打开  LM Studio ，进入  Local Server（开发者选项卡） 。
24.	2. 在右侧的设置面板（Server Settings）中，找到  Network Settings （网络设置）。
25.	3. 找到  Host / Binding Address （绑定地址）这一项：
26.			默认通常是 `127.0.0.1`。
27.			将其修改为 `0.0.0.0 `（这意味着允许所有网卡、所有局域网内的设备访问）。
28.	4. 端口（Port）保持默认的 `1234` 即可。
29.	5. 点击  Start Server  启动服务器。
30.
31.  ⚠️  Windows 防火墙提示 ：启动时，Windows 可能会弹出一个安全提示，问你是否允许该程序在“专用网络”或“公用网络”上通信。 请务必勾选并允许访问 ，否则 B 机的请求会被 A 机的防火墙死死挡住。
32.
33.第三步：在 B 机的 AnythingLLM 中配置接入
34.
35.	1. 在 B 机上打开  AnythingLLM ，进入设置 ->  LLM Provider 。
36.	2. 选择  LM Studio 。
37.	3. 在  LM Studio Base URL  中，不能再填 `localhost` 了，必须改成 A 机的实际局域网 IP。
38.	 格式修改为：`http://192.168.1.50:1234/v1` (请将 `192.168.1.50` 替换为你实际在第一步查到的 A 机 IP)
39.	4. 点击  Save Changes  保存。
40.		现在，你在 B 机的 AnythingLLM 里打字，A 机的 LM Studio 就会开始疯狂运转，并将结果通过网络实时吐回给 B 机。
41.
42.---------------
43. 💡 进阶避坑指南
44.	1.  A 机 IP 变动问题 ：家用路由器的 IP 地址通常是动态分配的。如果 A 机重启，IP 可能会变成 `192.168.1.51`，导致 B 机断连。如果频繁发生，建议在路由器的后台将 A 机的 MAC 地址与固定 IP 进行绑定。
45.	2.  局域网带宽影响 ：AnythingLLM 结合知识库（RAG）使用时，会将大段的代码或文档文本通过网络发送给 A 机。如果你们的局域网 Wi-Fi 信号很差或速度极慢，可能会感觉到明显的响应延迟（并非模型推理慢，而是网络传输慢）。
46.	3.  安全隐患 ：将 Host 改为 `0.0.0.0` 意味着 任何 接入你家这个路由器的设备（包括蹭网的人）只要知道了 IP，都能调用你 A 机的显卡算力。在安全的家里使用没有问题，但千万不要在公共场所的公共 Wi-Fi 下这样配置。
